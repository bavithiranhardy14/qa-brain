## Recommended Focus Areas

1. **Auto-approval boundary** — Precisely test ₹4,999 (auto), ₹5,000 (boundary — clarify inclusive/exclusive), ₹5,001 (manual)
2. **Waiting period enforcement** — Day 29 (blocked), day 30 (blocked or allowed — clarify), day 31 (allowed)
3. **Coverage limit exhaustion** — Claim at exactly remaining limit, claim 1 rupee over remaining limit
4. **File upload security** — Test malicious file payloads, double extension attacks (bill.pdf.exe), oversized files, 0-byte files
5. **Duplicate detection** — Same bill submitted by same user, same bill submitted by different users (agent vs. policyholder)
6. **Agent authorization** — Agent can submit but cannot approve; agent cannot access claims outside assigned customer portfolio
7. **Notification reliability** — Claim status change triggers both email and SMS; test when notification service is down

---

## Mitigation Suggestions

- Implement server-side file type validation (magic bytes check — not just extension)
- Use virus/malware scanning on all uploaded documents before storage
- Apply IDOR protection on claim reference numbers (use non-sequential IDs, enforce ownership checks)
- Make coverage limit decrement atomic (database transaction) to prevent race conditions on concurrent submissions
- Add rate limiting on claim submission endpoint to prevent claim flooding
- Log all claim events (submission, auto-approval, routing, status change) to the audit trail
- Add idempotency keys on claim submission to prevent duplicate submissions from network retries
